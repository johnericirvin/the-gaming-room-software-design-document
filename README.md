# the-gaming-room-software-design-document

This repository contains my software design document for The Gaming Room, created as part of CS 230 at Southern New Hampshire University. The client wanted to expand its game, Draw It or Lose It, from a single-platform application into a web-based application that could support multiple operating systems and users. The software needed to provide unique game and team names, support multiple players and teams, and offer a secure and scalable solution capable of meeting future growth requirements.

While developing this documentation, I believe one of my strengths was evaluating different operating platforms and recommending the most effective solution based on the client's needs. I carefully analyzed factors such as performance, scalability, security, and compatibility before making recommendations. This helped create a design document that clearly communicated development decisions to both the client and potential development team members.

Working through the design document before coding was especially helpful because it allowed me to fully understand the project requirements and system architecture. By identifying potential challenges and planning for them early, I was able to create a roadmap for development. The design process improved my understanding of how various system components interact and demonstrated the importance of planning before implementation.

If I could revise part of my work, I would expand the discussion of scalability and cloud-based deployment options. While I provided recommendations for future growth, adding more details about cloud infrastructure, resource allocation, and system optimization would strengthen the document and provide a more comprehensive solution for the client.

To address the user's needs, I carefully reviewed the client's requirements and translated them into design decisions that supported functionality, security, and usability. Features such as cross-platform compatibility, unique identifiers for games and teams, and efficient resource management were incorporated into the design. Considering the user's needs is essential because software is only successful when it effectively solves the problems it was created to address. Understanding those needs helps ensure that the final product provides value and a positive user experience.

My approach to software design involved analyzing requirements, researching available technologies, and evaluating potential solutions based on performance, security, and scalability. I applied object-oriented design concepts to create a structured and maintainable system. In the future, I plan to continue using requirements analysis, UML modeling, prototyping, and architectural evaluation techniques when designing software applications. As I work toward my career goal of becoming a software engineer, these strategies will help me develop reliable, efficient, and scalable software solutions.
